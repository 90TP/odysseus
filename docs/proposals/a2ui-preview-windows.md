# Proposal: A2UI preview windows

**Status:** proposed: talk it through with Cid before building
**Platforms:** desktop (Odysseus web UI) and Android (the WebView app)

## What

Let agents show live, interactive UI instead of only text and code. When an
agent is helping design an app (for example the clinical app), it can open a
preview window that shows the screen it's proposing: forms, cards, lists,
buttons. You can click around in it and ask for changes, and the preview
updates.

The format is [A2UI](https://github.com/a2ui-project/a2ui) (Agent-to-User
Interface): an open, Apache-2.0 protocol from Google. The agent sends a JSON
description of the UI. The app draws it with its **own** pre-approved
components. The agent never sends HTML or JavaScript.

The clinical app itself does not use Odysseus. Odysseus is only the workshop
where its screens are previewed while it's designed. Nothing here becomes
part of the clinical app unless that's chosen separately later.

## Is it safe? What goes to Google?

Checked against the A2UI source (`a2ui-project/a2ui`, Nov 2026):

- **The libraries send nothing to Google.** The renderers (`@a2ui/web_core`,
  `@a2ui/lit`, React/Angular/Flutter) and the Python `a2ui-core`/`a2ui-agent`
  packages contain no telemetry, analytics or calls home. Their dependencies
  are ordinary open-source libraries (lit, zod, pydantic, jsonschema). A2UI is
  a data format plus renderers; it has no Google service behind it.
- **Google can still be reached in three ways. Each one must be closed off:**
  1. **The model.** A2UI's ADK samples use Gemini, which *would* send your
     prompts to Google. Here the UI is generated by your own Odysseus model
     endpoints. Don't install `a2ui-adk` or any Gemini sample code.
  2. **The icon font.** The docs suggest loading Material Symbols from
     `fonts.googleapis.com`, which tells Google every time a page opens.
     Self-host the font under `static/fonts/`, or map icon names to local SVGs.
  3. **Images and links inside a preview.** An agent-made `Image` with a remote
     URL makes the browser fetch it. That leaks your IP and possibly data in the
     URL. Preview windows must only load `'self'`, `data:` and `blob:` images.
- **No code execution.** The renderer only builds components from its
  catalog, and unknown component types are rejected.
- **Patient data.** For the clinical app, previews use **made-up sample
  data only**. Real records never go into a preview or a prompt. A2UI keeps
  data separate from layout, so real data can later be bound locally without
  ever passing through the model.

Verdict: **safe to build**, provided every rule below is followed.

## How to build it

1. **Vendor, don't hotlink.** Build `@a2ui/web_core` + `@a2ui/lit` once into
   `static/lib/a2ui.bundle.min.js`, the same way the other libs in
   `static/lib/` are vendored. Pin the exact version and record it in
   `ACKNOWLEDGMENTS.md` (Apache-2.0). No CDN.
2. **Lit renderer for both platforms.** The Android app is a WebView onto the
   Odysseus web UI, so one web renderer covers desktop and Android. No
   Kotlin/Flutter renderer needed.
3. **Catalog:** start with A2UI's `basic` catalog (text, card, row/column, list,
   button, text field, checkbox, select, date). Add components only on purpose.
4. **Chat integration:** an agent reply containing a fenced ```` ```a2ui ````
   block opens a **preview window** (a tile/window like the existing tool
   windows). Messages are validated server-side against the catalog's JSON
   schema (`a2ui-core`/`jsonschema`) before they reach the browser. Invalid
   UI is shown as an error, never rendered.
5. **User actions** (button presses, form input) come back into the same chat
   as a structured message, so the agent can react and update the preview.
6. **Lock the preview down:** render inside a sandboxed same-origin iframe
   with its own CSP:
   `default-src 'none'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; script-src 'self'; font-src 'self'; connect-src 'self'`.
   Strip or block remote image URLs and links before rendering.
7. **Tests:** schema validation rejects unknown components and remote image
   URLs. A preview page makes no network request outside the app's own
   origin (Playwright check). The icon font is served locally.

## Out of scope (for now)

- Using A2UI inside the clinical app itself.
- Remote agents over A2A, and Gemini/ADK.
- Custom component catalogs beyond `basic`.
